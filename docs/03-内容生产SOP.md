# 内容生产 SOP

## 标准流程

| 阶段 | 输出 | 责任人 | 完成标准 |
|---|---|---|---|
| 1. 选题 | Issue + 内容简报 | 策划 | 受众、平台、目标、钩子、CTA 明确 |
| 2. 核验 | 事实清单 | 策划/业务负责人 | 动态信息有来源和核验时间 |
| 3. 采集 | 素材目录 | 摄影/编导 | 画面、口播、环境声、备选镜头齐全 |
| 4. 制作 | 初稿/粗剪 | 编辑 | 符合平台规格，版权来源明确 |
| 5. 审核 | 审核记录 | 运营/业务/安全 | 内容、事实、安全三项通过 |
| 6. 发布 | 链接与截图 | 运营 | 标题、封面、定位、话题、链接正确 |
| 7. 互动 | 评论台账 | 社群/客服 | 2 小时内处理高意向与风险评论 |
| 8. 复盘 | 数据与结论 | 数据/策划 | 24 小时首报、7 天完整复盘 |

## 审核分级

- **L1 常规内容**：品牌和文字审核即可。
- **L2 动态业务信息**：增加景区业务负责人审核，包括票务、开放、交通、活动。
- **L2 安全相关内容**：增加安全负责人审核，包括项目规则、天气风险、危险动作。
- **L3 重大对外信息**：管理负责人批准，包括事故、重大投诉、争议事件和媒体声明。

## 命名与素材规则

内容编号：`DSZ-YYYYMMDD-平台-序号`，例如 `DSZ-20260810-DY-01`。

素材目录建议：

```text
年份/月/内容编号/
├── 01-简报
├── 02-原始素材
├── 03-工程文件
├── 04-审核成片
├── 05-发布记录
└── 06-数据复盘
```

大体积素材放入批准的云盘或数字资产管理系统，在 Issue 中记录链接和权限；Git 仓库只保存轻量文档。

## 发布后动作

- 0–2 小时：回复高意向问题，识别事实错误和风险信号。
- 24 小时：记录曝光、观看/阅读、互动、主页访问和有效咨询。
- 72 小时：补充搜索词、评论问题和用户反馈。
- 7 天：完成转化数据、内容结论、可复用元素与下一步动作。

## 评论回复原则

- 能确认的事实直接、简洁回答，并给官方入口。
- 暂时无法确认时说明正在核实，不猜测、不承诺具体结果。
- 投诉先确认感受与事实，再转入工单；不要公开争辩。
- 人身攻击、违法信息和明显广告按平台规则处理并留证。
