# 新媒体运营驾驶舱 V1.0

独山子大峡谷 AI 营销中台的新媒体运营中心页面，独立于 OTA 销售驾驶舱和 OTA 舆情监测中心。

## 页面

- `/marketing-operations`：营销部每日统一入口，汇总今日待办、运营日历、本月目标和 AI 每日简报。
- `/`：平台运营总览、今日内容情况、爆款作品、热点趋势、模拟 AI 建议。
- `/content`：保留原内容数据列表，支持平台、日期和指标排序。
- `/insights`：保留原洞察分流入口，兼容已有链接，不再作为左侧一级菜单。
- `/insights/content`：独立“内容监测中心”，点击左侧一级菜单可展开或关闭抖音、快手、微博三个平台入口，按所选平台展示作品效果驾驶舱、TOP10、爆款分析、低效诊断和热点推荐效果关联。
- `/insights/fans`：粉丝分析中心 V2.1，包含7天/30天/自然月/自定义增长趋势、真实批次比较、画像与热词变化、期间作品表现、AI运营建议和周报导出。
- `/tasks`：任务管理中心 V2.0，以八阶段 Kanban 管理内容生产，支持拖拽状态、任务来源、优先级、协作人与作品自动关联，并输出 AI 执行分析和运营周报。
- `/content-planning`：AI内容策划中心，将抖音A级热点转为完整内容方案、任务、发布关联和7日AI复盘。

## AI内容策划中心 V1.0

`/content-planning` 是热点监测中心与任务管理中心之间的内容执行枢纽。首页从 `hot_topics + hot_topic_analysis` 读取抖音 A 级热点并展示今日推荐 TOP5；历史 `hot_topic_feedback` 效果会参与推荐指数校正。点击“查看方案”后，规则模型生成并持久化5个短视频标题、脚本、分镜、封面文案、发布时间、标签、话题、背景音乐、直播主题与播放/互动/涨粉目标。

一键生成任务会写入既有 `content_tasks`，通过 `source_type=ai_content_plan`、`source_id` 和 `content_plans.task_id` 保持可追溯关联。任务进入已发布后，任务中心优先继承内容方案已有作品关联，再按照同平台、发布时间窗口和标题相似度保守匹配 `social_posts`；证据不足时保持等待状态，不强行绑定。作品发布时间满7天后，定时任务会生成 `content_plan_feedback`，输出达成情况、优势、不足和是否继续推荐类似内容。V1.0 不开放快手、微博策划入口，也不生成模拟作品指标。

## 任务管理中心 V2.0

任务看板固定为“待策划、待拍摄、拍摄中、待剪辑、待审核、待发布、已发布、已复盘”八列，桌面端支持拖拽，平板和移动端以横向滚动保留完整流程，同时提供状态下拉作为无障碍和触屏回退操作。任务记录负责人、协助人、平台、内容类型、截止时间、优先级，以及热点监测、AI内容策划、人工创建或节日活动来源。

发布作品关联由服务端和每日任务自动检查，不要求人工匹配。已关联任务基于 `content_plans` 目标与 `social_posts` 实际播放、互动和涨粉计算达成率，并显示是否按时完成；没有目标或作品数据时明确显示等待，不生成永久模拟指标。运营周报按北京时间自然周统计任务数、完成率、爆款数、目标达标率和负责人完成情况，同时显示最近 `collection_logs` 数据更新时间。

## 营销运营中心 V1.0

`/marketing-operations` 不新增数据库，只读汇总现有热点、AI分析、任务、内容方案、作品、粉丝增长和采集日志。今日待办按北京时间当天严格统计 A 级热点、待拍、待发布、逾期和待复盘内容；没有当天数据时显示“暂无”，不会回退为模拟结果。

运营日历支持月份切换，统一展示 `content_tasks` 中的发布计划、直播计划和节日活动来源任务，以及 `hot_topics + hot_topic_analysis` 中值得跟进的热点事件。元旦、劳动节和国庆节使用系统内置固定日期规则并明确标注，不写入数据库。

营销目标以当前选择月份为口径：作品与直播完成率来自任务状态，粉丝增长实际值来自 `fan_growth_records`（缺失时使用作品涨粉汇总），粉丝和播放目标来自 `content_plans`。未设置目标时显示“未设目标”，不将实际值误报为达成率。AI每日简报汇总今日热点、昨日最佳作品、风险提醒和可执行建议，并显示最近采集日期。
- `/imports`：保留的数据导入兼容路径，与数据采集中心的“数据导入”Tab 共用同一组件和接口。
- `/hot-topics`：热点 CRUD、TOP10 排行、景区关联评分与规则型 AI 选题推荐。
- `/ai-analysis`：作品爆款评分、五维内容评分、平台分析、选题推荐与 AI 日报/周报。
- `/collector`：新媒体数据采集中心；通过“自动采集 / 数据导入”两个独立 Tab 统一管理 Chrome 采集、Excel、图片上传、校验及日志。
- `/comment-insights`：分析真实评论的情绪、关键词和游客需求，输出内容运营建议。

## 数据接口

- `GET /api/marketing-operations?month=YYYY-MM`：汇总今日待办、指定月份运营日历、营销目标和 AI 每日简报；只读复用现有业务表。
- `GET /api/dashboard`：汇总 `social_accounts`、`social_posts`、`hot_topics`、`content_tasks`。
- `GET /api/posts`：查询和排序作品。
- `GET /api/tasks`：查询八阶段任务、自动关联结果、AI执行指标与本周运营统计。
- `POST /api/tasks`：新增含来源、协助人和优先级的任务。
- `PATCH /api/tasks`：拖拽或选择后修改任务状态，进入发布阶段时触发作品自动关联。
- `PUT /api/tasks`：手动触发一次作品自动关联检查；同一逻辑也由每日任务执行。
- `GET /api/imports`：查询导入记录。
- `POST /api/imports`：保存 Excel 或图片文件并创建导入记录。
- `PATCH /api/imports`：记录文件识别结果。
- `DELETE /api/imports`：删除指定批次写入的数据，保留导入日志。
- `POST /api/imports/confirm`：服务端复核并以事务方式写入作品，或人工确认图片。
- `GET /api/hot-topics`：查询热点、TOP10、关联分析和选题推荐。
- `POST /api/hot-topics`：新增热点并自动计算景区关联度。
- `PATCH /api/hot-topics`：编辑热点并重新计算关联度。
- `DELETE /api/hot-topics?id={id}`：删除指定热点，不触碰历史作品。
- `GET /api/ai-analysis`：读取作品、热点和账号数据，生成规则评分、平台洞察、选题及运营报告。
- `GET /api/collections`：查询采集日志及成功、失败汇总。
- `POST /api/collections`：校验抖音 Chrome 采集文件并创建待确认日志，不写作品表。
- `POST /api/collections/confirm`：再次校验，新增作品并安全更新已有作品的最新指标。
- `POST /api/collections/comments`：校验抖音评论采集文件并创建待确认日志，不写评论表。
- `POST /api/collections/comments/confirm`：再次校验、关联已有作品、跳过重复评论并写入 `social_comments`。
- `POST /api/collections/douyin-v3`：校验抖音 V3.0 粉丝、作品、详情和评论批次，仅返回预览，不写数据库。
- `POST /api/collections/douyin-v3/confirm`：要求显式人工确认，以事务幂等写入粉丝、增长、作品、划走率、观众画像和评论，并记录完整采集日志。
- `DELETE /api/collections?id={id}`：回滚指定采集批次的作品，保留采集日志。
- `GET /api/comment-insights`：查询当前评论洞察结果。
- `POST /api/comment-insights`：运行规则模型，并将分析结果写回 `social_comments`。
- `GET /api/insights/content`：读取 `social_posts`、`hot_topics` 和 `viral_videos`，生成作品评分、五类内容占比、爆款视频库对比、AI 日报、爆款和内容转粉关联。
- `GET /api/insights/fans`：读取账号、粉丝画像和增长记录，支持 `trend=7d|30d|month`；无增长记录时以作品涨粉作为明确标注的回退趋势。

前端只依赖这些版本化接口。未来接入平台自动采集时，可在服务端扩展数据写入流程，不需要重写页面。

## 数据导入能力 V1.0

Excel 支持以下字段名：`标题`、`平台`、`发布时间`、`播放量`、`点赞`、`评论`、`收藏`、`分享`、`涨粉`。支持中文平台名或内部平台编码。

导入采用“保存文件 → 本地识别 → 数据预览 → 服务端复核 → 事务写入”的流程。任何一行校验失败都会拒绝整批写入；成功作品记录 `import_log_id`，允许按批次安全回滚。原始上传文件存入独立对象存储，数据库通过 `data_import_logs` 保留导入历史。

图片导入当前只保存文件、创建记录并等待人工确认；OCR 接口已经预留，但 V1.0 不调用 OCR 服务。

该能力已嵌入 `/collector` 的“数据导入”Tab。原 `/imports` 页面继续保留并复用同一个 `DataImportPanel`，用于兼容旧链接，不在左侧菜单重复展示。

## 多平台热点监测与 AI 选题推荐中心 V2.0

`hot_topics` 在原有字段上增加 `keyword`、`status` 与 `created_at`，保留 `collect_time` 作为最近采集或编辑时间，确保驾驶舱已有查询兼容。关联度由服务端规则引擎根据热点关键词、景区名称和 `social_posts` 历史标题/标签计算；选题推荐返回标题、内容方向、适合平台和拍摄建议。

页面取消“平台热点趋势”和“内容热度分析”两个大入口。左侧热点监测中心展开抖音、快手、微博三个平台入口，并作为唯一的平台选择方式；页面内不再重复显示平台选择按钮。页面只读取 `HOT_TOPIC_DATA` 中对应平台的 WorkBuddy 数据，标题、TOP20、AI报告和运营建议全部跟随当前平台切换。

热点监测中心顶部增加独立数据周期选择器，支持“今日、昨日、近一周、自然月、自定义”，默认显示北京时间今日。周期筛选按 WorkBuddy `publish_time`（采集时间）作用于平台 TOP20 和 AI 选题推荐；自然月与自定义继续复用系统统一的月份面板和双月日历，不改变其他页面默认昨日的全局周期规则。

页面提供“分析报告”和“TOP20列表”两种展示方式，默认进入分析报告。报告版式参考 WorkBuddy 日报，使用当前筛选周期和平台的真实数据生成监测摘要、最多 50 条热点卡片、借势判断、关联度、拍摄方向、短视频标题、直播主题及今日运营建议；未运行 AI 分析的热点明确显示待分析，不补造建议。原有 TOP20 表格和逐条 AI 分析入口继续保留。

AI 热点分析综合当前 WorkBuddy 热点、独山子大峡谷景区资源与 `social_posts` 历史内容，输出关联度、是否推荐跟进、推荐标题和拍摄方向。平台差异化建议分别面向抖音短视频、快手互动与直播、微博品牌传播。

升级迁移不会删除已有独山子大峡谷相关内容；现有抖音内容统一标记为 `douyin_content_hot` 并进入内容热度分析。以后只有经过官方榜单预览确认的数据才写入对应官方来源类型。官方榜单 AI 用于判断是否适合跟进，内容热度 AI 用于输出视频制作方向，避免把搜索内容热度标成平台热点。

抖音热点监测中心 V1.0 使用当前已登录 Chrome 环境读取抖音官方今日热榜。系统先通过 `GET /api/hot-topics/douyin/preview` 返回标准化预览（官方 TOP10 展示、Top50 机会分析），不会直接写库；只有用户在页面明确确认后才调用 `POST /api/hot-topics/douyin/confirm`，批量更新 `hot_topics` 并记录 `collection_logs`。`hot_topics` 新增 `ranking`、`source_url`、`source_record_id` 与 `collection_log_id`，首次采集无历史快照时趋势标记为 `new`，不生成虚假涨跌。当前阶段仅支持抖音。

### 外部 Agent 热点接入

`POST /api/hot-topic/import` 接收 WorkBuddy 等外部 Agent 提供的热点数据，本系统不在该接口内执行采集。接口支持 JSON，以及 `multipart/form-data` 上传的 XLSX/XLS；Excel 文件字段支持中英文表头。必填字段为 `source_agent`、`platform`、`topic_name`、`heat_value`，平台可使用 `douyin`、`kuaishou`、`weibo`、`web`（也接受“抖音、快手、微博、全网”）。单次最多 500 条，Excel 最大 5MB，任一行校验失败时整批拒绝。

日常 Agent 调用保持增量更新语义不变。经过人工核验的 JSON 可显式传入 `replace_existing: true`，系统会在同一个 D1 批处理中替换 WorkBuddy 当前快照；任一写入失败时整批回滚，避免出现先清空后写入失败的中间状态。

热点监测页面在选择 JSON 文件后提供“替换当前数据”操作，用于人工核验后的快照覆盖；普通“导入数据”仍保持原有增量导入方式，Excel 导入逻辑不变。

AI Agent数据接入中心 V1.0 使用独立实体表 `HOT_TOPIC_DATA` 保存 WorkBuddy 热点。字段包括平台、排名、热点标题、原始热度、关键词、链接、发布时间、分类、来源 Agent，以及 AI 关联评分、分析和推荐。`source_agent` 由接收服务固定为“WorkBuddy热点监测Agent”，同来源、同平台、同标题和同发布时间的数据重复导入时更新原记录。

本机导入服务 `scripts/import-workbuddy-hot-topics.mjs` 会读取 `~/Desktop/景区AI营销数据/hot_topics/` 中日期最新的 `hot_topic_YYYYMMDD.json`，校验后提交至 `POST /api/hot-topic/import`。运行 `pnpm import:workbuddy-hot-topics -- --dry-run` 可仅检查最新文件而不写库；正式导入可配置 `WORKBUDDY_API_BASE_URL`、`WORKBUDDY_AGENT_KEY`，私有站点机器调用还需 `WORKBUDDY_SITES_BEARER_TOKEN`。该服务不访问抖音、快手、微博或其他平台，不包含采集功能。

热点监测中心通过 `GET /api/hot-topic-data` 展示 WorkBuddy 数据。点击每条热点的“AI分析”会调用 `POST /api/hot-topic-data/analyze`，重新计算与独山子大峡谷的关联度、是否值得跟进、推荐拍摄方向、短视频标题和直播主题。

当前 `recommendationEngine` 为 `rules-v1`。接口响应预留 `/api/v1/social/ai/topic-recommendations` 作为未来大模型适配路径，但 V1.0 不调用外部模型，也不实现自动采集。

## AI 内容分析中心 V1.0

内容分析中心直接读取 `social_posts`、`hot_topics` 和 `social_accounts`，不新增永久模拟数据。综合评分满分 100 分，权重为：视觉吸引力 25%、标题质量 20%、互动能力 20%、传播能力 20%、热点匹配度 15%。爆款评分单独结合相对播放表现、互动率、分享率和涨粉计算。

V1.0 尚未识别视频画面，因此视觉吸引力使用相对播放、收藏率、内容类型等数据代理指标，并在页面明确说明。AI 日报和 AI 周报遵循全局日期筛选范围；报告包含账号表现、优秀作品、问题分析和行动建议。当前分析引擎为 `content-rules-v1`，预留 `/api/v1/social/ai/content-analysis` 作为未来大模型接口。

## 全局日期筛选器 V1.0

运营驾驶舱顶部提供“今日、昨日、近一周、自然月、自定义”五种数据周期，默认昨日。选择“今日”会按北京时间自动使用当天起止日期。选择结果通过统一的 `preset`、`from`、`to` 参数同步到运营驾驶舱、内容分析、粉丝分析、游客评论洞察和 AI 内容分析，并在页面间保留最近一次选择。

“自然月”使用年份导航和十二个月网格，可选择当前月或历史月份；当前月统计到今天，历史月份统计完整自然月。“自定义”使用相邻双月日历选择开始和结束日期，支持按月、按年切换并在确认前显示完整区间。两种面板均沿用营销中台绿色状态色。

服务端会分别按 `social_posts.publish_time`、`social_comments.comment_time`、`social_fans.collected_at` 和 `fan_growth_records.record_date` 限定统计范围，刷新发布数量、播放和互动、作品排行、粉丝变化及评论分析。自定义范围要求开始日期不晚于结束日期；参数无效时安全回退到昨日。不新增字段或数据表，也不改变采集、导入及 OTA 模块。

## 新媒体数据采集中心 V1.0

数据采集中心将现有能力汇总到 `/collector`，顶部提供两个功能 Tab：“自动采集”保留 Chrome 抖音作品、评论、预览确认、进度和采集日志；“数据导入”保留 Excel、图片上传、导入预览、重新导入和批次回滚。两种方式最终均写入 `social_posts`：Excel 数据通过 `import_log_id` 追踪，Chrome 数据通过 `collection_log_id` 追踪。

左侧菜单只显示“数据采集中心”，不再分别展示“数据导入中心”和“智能采集中心”。本次整合只调整信息架构和组件复用，不删除原页面、接口或数据库表。

抖音 Chrome 采集流程：

1. 在 `/collector` 下载 `douyin-collector-v1.zip`，解压后在 `chrome://extensions` 开启开发者模式并加载扩展目录。
2. 运营人员自行登录有权管理的抖音创作者账号，打开作品管理列表并加载需要采集的作品。
3. 点击扩展的“采集当前页面”，扩展读取当前页面已显示的作品卡片并导出标准 JSON。
4. 将 JSON 上传至 `/collector`。服务端校验平台、发布时间、指标、作品链接、内容类型和重复作品。
5. 预览无误后人工确认。系统使用事务整批写入 `social_posts`；任意错误均拒绝整批入库。

扩展不读取 Cookie、密码或浏览历史，不绕过登录、验证码、风控或平台限制，也不直接连接数据库。抖音页面结构变化后，需升级扩展中的页面适配器。快手、微博的自动采集仍为后续阶段，当前继续使用 Excel 人工导入。

### 抖音评论详情采集 V1.0

作品列表采集逻辑保持不变。运营人员可从作品卡片的评论入口进入评论详情，由扩展展开当前可见的回复并采集每个作品最多 50 条评论，字段包括用户名、评论内容、评论时间和评论点赞数。

评论数据继续执行“标准 JSON → 数据校验 → 页面预览 → 人工确认 → 事务写入”的审批流程。确认前不会写入 `social_comments`；确认时按作品链接关联已有 `social_posts`，作品不存在、字段错误或单作品超过 50 条都会拒绝整批写入。成功批次通过 `collection_log_id` 关联采集日志，`collection_logs.entity_type` 标识作品或评论批次，`comment_count` 记录实际评论入库数。删除评论采集批次时只回滚该批评论，保留日志，不影响对应作品。

### 抖音 30 天真实采集测试 V1.0

30 天测试范围支持最多20个作品、每个作品最多50条评论。采集 JSON 可携带日期范围、处理进度和失败明细；采集中心在预览区显示百分比和失败原因，失败详情同时持久化到 `collection_logs.error_message`。作品确认时新增缺失记录并更新已有作品的最新指标；评论确认时按“作品、用户名、评论内容”去重，不因相对时间变化重复入库。

本次 2026-07-10 至 2026-08-08 的测试报告位于 `docs/douyin-30day-collection-test-v1.md`。预览阶段不写数据库，必须先确认作品，再确认评论；快手、微博以及定时任务均未实现。

数据库仅初始化表结构，不再自动写入运营账号、演示作品、虚构粉丝量或任务数据。

### 抖音智能采集中心 V2.1

V2.1 将粉丝分析与作品详情统一为一个标准 JSON 批次。粉丝数据包括精确粉丝总量、增长趋势、性别、年龄、地域、兴趣和活跃时间，确认后写入 `social_fans` 与 `fan_growth_records`。作品数据在保留 V1.0 基础指标的同时新增完播率、平均播放时长和流量来源；单作品年龄、地域、性别画像写入新增表 `content_audience_analysis`，评论继续写入 `social_comments`。

预览完整率按三组独立计算：粉丝为总量/增长/五类画像，作品为基础字段/流量/三类观众画像，评论为数量/内容/热词。三组均达到 80% 才开放“人工确认并入库”；任何一组未达标时按钮禁用并列出失败字段。

新增接口：

- `POST /api/collections/douyin-v2`：校验 V2.1 JSON、计算三类完整率并生成预览；该接口不连接数据库、不创建日志、不写业务表。
- `POST /api/collections/douyin-v2/confirm`：仅在三类完整率均达到 80% 且人工确认后创建采集日志，以同一数据库事务写入粉丝快照、增长记录、作品、作品观众画像和评论。
- `DELETE /api/collections?id={id}`：V2.1 已确认批次按评论、观众画像、作品、增长、粉丝顺序回滚，日志保留。

V2.1 真实预览范围为 2026-08-01 至 2026-08-07。已读取精确粉丝 161,370 及性别、年龄、地域、兴趣画像，并复用该范围已复核的 3 条作品和 10 条评论；第一条作品补充了完播率、平均播放时长、主要流量来源和观众地域，第二条作品补充了实时播放量与完播率。粉丝增长、活跃时段及未稳定读取的作品图表全部记录为失败项，不生成模拟数据。预览文件位于 `data/collection-previews/douyin-v2-dushanzi-2026-08-01_2026-08-07.json`；当前完整率未达门槛，不能确认入库。

### 抖音平台数据采集 V3.0

V3.0 已完成 2026-07-01 至 2026-07-30 的抖音完整闭环测试。人工确认后的同一事务写入粉丝快照 1 条、粉丝增长区间汇总 1 条、作品 17 条、作品观众分析 3 条和非作者顶级评论 14 条；`collection_logs.entity_type` 使用 `douyin_v3`，失败字段和未稳定读取原因保留在日志中。

作品新增 `skip_rate` 保存划走率。缺失的作品链接、平均观看时长、流量来源和观众画像保持为空；V3.0 确认接口按账号和标题更新作品，并按作品、用户名、内容和评论时间跳过重复评论，可安全重新执行。当前作品全部字段完整率为 66.67%，因此适合“基础数据先入库、详情后补采”，尚未达到建议的 80% 正式运行门槛。完整报告位于 `docs/douyin-v3-july-collection-preview.md`，标准预览数据位于 `data/collection-previews/douyin-v3-dushanzi-2026-07-01_2026-07-30.json`。

## 游客评论洞察中心 V1.0

洞察中心读取 `social_comments` 和关联作品，使用 `comment-rules-v1` 规则模型识别正向、负向和中性情绪，提取热门关键词，并将游客需求归入旅游攻略、交通路线、价格咨询、项目体验、亲子需求、老人需求、服务评价和其他八类。分析结果持久化至 `sentiment`、`keyword`、`user_need` 和 `ai_analysis`，不覆盖评论原文。

页面展示评论总量、情绪比例、热门关键词、需求分布和逐条分析结果，并根据主要需求生成建议拍摄主题、标题方向和内容优化建议。预留 `/api/v1/social/ai/comment-insights` 作为未来大模型适配接口；V1.0 不调用外部模型，也不自动回复游客。

## 内容监测中心 / 作品数据模型 V2.1

`/insights/content` 已从原洞察入口拆分为左侧一级模块“03 内容监测中心”。进入模块后显示抖音、快手、微博三个子入口；页面将 `platform` 传给 `/api/content-monitoring`，分别读取 `social_posts`、`social_comments` 和 `hot_topic_feedback`，展示所选平台的今日发布、周期播放、赞评藏转、互动率和 TOP10 作品。未采集的平台明确显示空状态，不生成模拟数据。

爆款分析使用现有规则模型，结合播放相对表现、互动率、完播率和真实评论样本，输出爆款原因、内容结构、标题特点和拍摄方式；低效诊断根据周期平均播放、互动率和 AI 评分给出播放低原因与优化建议。热点关联区将已经关联发布作品的 `hot_topic_feedback` 与作品效果复盘结果合并展示，明确热点推荐是有效、无效还是待评估。未采集字段保持空值，只有源数据真实为 0 时才显示 0，不生成模拟平台数据。

WorkBuddy 深度 V2.1 固定从 `~/Desktop/新媒体内容监测/抖音/` 只读扫描 `douyin_posts_deep_*.json`。脚本按 JSON 可解析性、源 `collection_time`、批次、完整度和实际作品数选择最新未处理文件，不以 Finder 修改时间作为唯一依据；SHA-256 已完成记录会被服务端拒绝重复处理。运行 `npm run import:workbuddy-douyin-deep` 生成预览，追加 `-- --confirm` 明确确认后才写入业务表。

V2.1 将作品稳定信息、采集快照、真实图表点、流量质量、自然来源、独立 DOU+、作品级观众、评论热词、评论和回复分层保存。私密作品保留主记录和私密快照，所有不可读指标为 NULL；无真实时间轴的趋势只保留点序，评论总览、页面加载数和 JSON 明细数分别保存。详情页增加“数据趋势”，并明确区分作品观众画像与账号粉丝画像。

“同行业对比分析”已升级为“爆款内容对比分析”，不再预置或绑定固定景区账号。新增 `viral_videos` 爆款视频库，按旅游类爆款、景区类爆款、新疆旅游爆款、自然风景爆款四个赛道保存真实样本，并记录视频结构、标题方式、前三秒内容、拍摄方式、互动方式、评论反馈、爆款原因、可复制元素和独山子大峡谷内容建议。

页面可按四类样本切换，展示平均播放、互动率、爆款作品明细和六维结构对比，并输出爆款原因、可复制元素及适配建议。没有真实样本时明确显示“待采集”，不生成虚构播放或互动数据。`account_name` 仅作为可选来源信息，不作为对标维度；`source_type`、`source_record_id`、`raw_payload` 和 `collection_log_id` 支持未来 Chrome、Excel、平台 API 与人工录入。

## 粉丝分析中心 V2.1

`/insights/fans` 继续作为左侧一级模块“03 粉丝分析中心”。V2.1 优先支持抖音，读取 `fan_collection_batches`、`social_fans`、`fan_growth_records`、`fan_profile_records` 与 `social_posts`。账号快照、周期增长和画像明细分层保存，每次采集新增批次，不覆盖历史画像。

画像分析展示年龄、性别、地域、兴趣、设备、活跃度和关注热词，并自动比较最近两次真实画像快照。活跃时间等平台未提供字段保持 NULL/unavailable。内容吸粉分析以 `social_posts.fans_growth` 作为单作品涨粉值，以 daily 粉丝记录作为背景校验；区间汇总不伪装成每日趋势。

规则模型自动生成本周期粉丝分析、增长原因、流失原因、最佳涨粉作品和下周内容建议。周报支持 PNG 直接下载；PDF 通过系统打印窗口导出，选择“另存为PDF”即可。导出文件只使用当前页面真实数据，缺失画像或作品涨粉时明确显示等待，不补造数据。

跨批次分析只读取 `fan_collection_batches.status=completed` 且同平台、同账号的最近两个真实批次，比较粉丝总量、净增长、吸粉、脱粉、回访粉丝，以及性别、年龄、地域、兴趣、设备、活跃度和100条关注热词。系统自动关联两次真实采集时间之间的 `social_posts`，但只将作品表现作为同期分析背景，不作未经验证的因果判断。当前只有一个真实批次时，页面明确显示暂无上期数据、等待画像变化和期间内容表现，不读取旧版无批次快照补足上期。

原 `/insights` 分流页、内容转粉和作品详情全部保留。真实画像尚未采集时保持空状态；每日增长序列不足时明确提示数据点不足，不再使用作品涨粉生成模拟折线。

### 平台主题色切换 V1.0

系统仅保留抖音、快手、微博三个平台。内容监测中心通过左侧子入口切换三个平台；粉丝分析中心保留“全部平台、抖音、快手、微博”四种状态。全部平台沿用营销中台绿色；抖音使用纯黑主色并搭配红色、青色强调，快手使用纯橙色，微博使用纯红色。平台主题全部使用纯色，不使用渐变；主题只作用于平台入口、洞察卡片顶部、图表和关键指标，不改变页面背景或其他模块。

选择具体平台后，页面标题会同步显示“抖音内容分析”“微博粉丝分析”等当前状态，并通过状态徽标和选中卡片强化识别。粉丝分析的“全部平台”汇总账号规模和增长趋势，画像仍要求选择具体平台查看，不跨平台混合画像。

### 作品数据分析

内容分析页的“爆款作品排行”为每条作品提供“数据分析”入口。详情页按“流量分析、数据趋势、观众分析、评论热词、评论管理”分开展示，读取最新真实作品快照及各明细表；私密、partial、unavailable、failed 和评论点赞不可读状态不会被改写成 0。

互动率、点赞率、评论率、收藏率、分享率和涨粉转化率由真实作品指标计算。V2.1 已为完播率、平均播放时长、平台流量来源和单作品观众画像建立存储与详情展示；字段尚未采集时仍显示“待采集”，不生成模拟占比。

## 本地运行

要求 Node.js 22.13+ 和 pnpm。

```bash
cp dev.vars.example .dev.vars
pnpm install
pnpm dev
```

打开 `http://localhost:3000`。新数据库默认保持空状态，账号、作品、粉丝和任务均需通过系统功能或真实采集流程写入。

## 验证

```bash
pnpm db:generate
pnpm build
pnpm test
pnpm lint
```

数据库 Schema 位于 `db/schema.ts`，生成的 D1 迁移位于 `drizzle/`。项目根目录的 PostgreSQL 迁移仍是正式中台数据库设计基线；该 D1 迁移用于本应用的本地预览和 Sites 运行环境。

## 当前边界

- Chrome 自动采集仅支持抖音作品管理和评论详情页；快手、微博和平台 API 自动采集尚未实现。
- 图片上传未接入复杂 OCR，仅保存记录和人工确认。
- 未实现自动发布、自动回复或无审批 AI 执行。
- 不访问、不修改 OTA 模块的页面、接口或数据库表。
- AI 运营建议为 V1.0 模拟结果，并在页面明确标注。
- AI 内容分析采用可解释规则模型，不进行画面识别，也不调用外部大模型。
- 游客评论洞察采用关键词与情绪词规则，结果用于运营辅助，不替代人工判断或自动回复。
- 粉丝画像只展示 `social_fans` 中的真实快照；当前不实现粉丝自动采集，也不生成模拟地域、年龄或兴趣数据。
